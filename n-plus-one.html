The N+1 query: the loop that looks free

One query became a hundred and one, and a hundred of them are pure round-trip latency.

Fetch a hundred posts, then read each post's author inside the loop. It looks innocent in review. It runs 101 queries.

Where it comes from

ORMs make related data feel like a property. In Laravel, $post->author looks like a field, but the first time you touch it the ORM quietly runs a query. Do that inside a loop over a hundred posts and you get one query for the posts plus one per post for the authors — N+1.

$posts = Post::all();          // 1 query
foreach ($posts as $post) {
    echo $post->author->name;  // +1 query, each time
}

The database was never slow. You called it a hundred times and blamed it once. Most of that time is not query execution — it is network round trips, paid serially.

The fix: say what you need up front

Eager loading declares the relationship before the loop, so the ORM fetches all the authors in a single follow-up query using WHERE id IN (...):

$posts = Post::with('author')->get();  // 2 queries, total

A hundred round trips collapse into two. The result is identical; only the number of times you crossed the network changed.

How to catch it

N+1 is invisible in code review because the loop looks fine — you have to see the query count. Enable query logging in development, or use a tool that counts queries per request and warns when one page fires dozens. Once you can see the number, the pattern is obvious; until then, it hides.
